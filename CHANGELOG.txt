=====================================================================
1. WHAT THIS APP IS
=====================================================================
Single-user local ERP, POS-first. Only active modules: POS, Inventory (with Categories + Deleted tabs), Suppliers, Sales/Receipt.
Currency: tugrik "₮". money() filter prints whole amounts as 1,900,000₮ (no ".00"); decimals print as 1,900,000.50₮.

Removed from the earlier Vortex-inspired build at user request:
- stock locations / per-location stock
- stock moves / transactions
- transfers
- cash sessions (opening/closing till, session reports)
- separate Categories page (merged into Inventory)
- separate Deleted-products page (merged into Inventory "Deleted" tab)
- dashboard (POS became the main interface)
- payment methods CashPay and leasing (rows deleted from payment_methods)
Note: some old tables (stock, stock_movements, cash_sessions, locations) may still physically exist in erp.db but nothing in app.py reads or writes them.

DB backups taken during this work:
/tmp/erp_backup_2243.db       (before hand-fixing the subagent upgrade crash)
/tmp/erp_before_merge_2257.db (before merging categories into inventory + removing locations/moves/sessions)

E. Animation rebuild (the "choppy" complaint)
What was wrong: animations were repainting the main thread — transitions on background/box-shadow/border-color/filter,
CSS gradients (gradients are NOT interpolatable, so hover looked like a hard cut), a 180px radial-gradient ripple on
every button, and backdrop-filter: blur(10px) on the modal.
What it is now (compositor-only: transform + opacity):
- :root easings: --spring cubic-bezier(.2,.9,.3,1) for interactive states, --spring-out cubic-bezier(.16,1,.3,1) for
  modal/dropdown entrances.
- buttons: transition transform .16s var(--spring); hover translateY(-1px); active translateY(1px) scale(.985) .09s.
- ripple pseudo-elements removed (leftovers `.qtybox .btn.tiny::after{content:none}` and `.sug::after{content:none}` are inert).
- product card hover no longer swaps gradients (border + static box-shadow only).
- modal: fade-in .20s backdrop + modal-rise .28s translateY(12px) only; backdrop-filter removed.
- dropdown: suggest-in .18s translateY(-4px) only.
- `@media (prefers-reduced-motion: reduce)` disables animation/transition.
Reference used earlier: Chrome "Modern Web Guidance" physics-based easing advice (animate transform/opacity, avoid
animating blur/backdrop-filter, spring-ish curves).

Search audit (every search path checked - POS box, browse box, autocomplete API, Inventory,
barcode/SKU scan, Sets, Sales)

Found and fixed
- Multi-word queries were matched as one contiguous substring everywhere: 'rtx 5060' or
  'gaming sandal' found nothing unless the name contained that exact spacing/order. Now every
  typed word must match somewhere (AND across words, OR across name/SKU/barcode/brand).
- Case: SQLite LIKE/LOWER only fold ASCII, so uppercase Cyrillic (ШИРЭЭ, ХАР) returned 0 hits
  against names stored as "Ширээ". A norm() UDF (Python casefold) is registered on each
  connection and all searches compare norm(column) - Cyrillic now matches in either case.
- User-typed % and _ were live SQL wildcards: q='_' matched 52 products, q='%' matched all.
  They are escaped and used with ESCAPE '\', so they search literally.
- Browse grid priced everything 0₮: /pos/search returns price/price_num but the JS read
  p.amount. API now returns amount as well.
- Sets were searched two different ways - server used whole-query substring, the browse box JS
  used all-words - so results changed depending on whether the grid was re-rendered. set_catalog
  now uses the same all-words rule and also searches set description/components.
- /pos/scan compared barcode/SKU with LOWER() (ASCII only) -> norm() equality.
- Sales search only covered ref/phone/note and was single-substring; it now also matches the
  item names stored on the sale (sale_items.name) and applies the word/case/escape rules.
- Race conditions: POS live box, POS browse box and Sales live search had no ordering guard, so
  a slow response for an older term could paint over a newer one (the "works then doesn't"
  symptom) and a failed fetch was an unhandled rejection. All three now use a sequence token,
  re-check the current input, and show an error on failure.
